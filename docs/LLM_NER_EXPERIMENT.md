# SH2026 LLM Spatial NER Experiment

Status: **protocol frozen before formal LLM inference**

This experiment completes the LLM column of the Spatial NER row in the SH2026 method × task framework. It deliberately separates **model capability under a fixed NER ontology** from **representational reach under a broader spatial ontology**.

## 1. Research questions

### Condition A: constrained TOPONYM-only NER

Hold the task ontology constant and compare:

- deterministic rules/gazetteer;
- contextual spaCy NER;
- pinned Hugging Face transformer NER;
- schema-constrained LLM TOPONYM extraction.

Question:

> If all methods are asked to identify the same named-place category, does the LLM improve recognition performance, and at what latency, cost and review burden?

This is the apples-to-apples LLM NER condition.

### Condition B: full SH2026 spatial-span extraction

Permit the LLM to use the frozen SH2026 span inventory:

- `TOPONYM`
- `GEONOUN`
- `SPATIAL_RELATION`
- `DISTANCE`
- `DIRECTION`
- `TIME`
- `MOVEMENT_CUE`
- `TRANSPORT_CUE`
- `SUBJECTIVE_DESCRIPTOR`
- `SENSORY_DESCRIPTOR`
- `DEICTIC_REFERENCE`

Question:

> What additional spatial information becomes representable when the output ontology is expanded beyond conventional named-place NER?

This condition must not be described as an accuracy win over TOPONYM-only systems merely because its schema is richer.

## 2. Formal OpenAI condition

For SH2026 LLM NER v1, freeze the formal OpenAI run as:

- provider: `openai`
- model: `gpt-5.6-sol`
- API: Responses API
- structured output: strict JSON Schema
- reasoning effort: `none`
- temperature: not explicitly set; record the API/model default in the manifest
- repetitions: 1 for the conference sprint unless a new protocol version explicitly introduces repeated runs
- source offsets: never generated by the model

`reasoning_effort=none` is intentional for this bounded recognition task. A later journey/interpretive condition may use a different reasoning setting, but that becomes a different task configuration rather than silently changing the NER condition.

## 3. Evidence-first output contract

The model proposes for each span:

- exact source `text`;
- one allowed `label`;
- verbatim `evidence_quote` containing the span;
- `certainty` (`explicit`, `contextual_inference`, or `ambiguous`);
- annotation `confidence`.

The model does **not** return offsets. `spatio_textual.llm_spans` grounds the literal span against the source and computes offsets locally.

Core principle:

> **LLM proposes -> software grounds -> evaluator scores -> human reviews where needed.**

If a model returns an unmentioned place, malformed evidence or an occurrence that cannot be disambiguated, the software does not invent an offset. The proposal is retained for audit and counted appropriately.

## 4. Data layers

### Frozen synthetic holdout

Primary controlled comparison uses `benchmarks/holdout_v1.jsonl`, generated deterministically with SHA-256:

`be9c526af68230f22cb92507af69d8aacea8cbb5bd7ad5dfcf3d7c16767fdb9b`

Run both Condition A and Condition B here.

### CLDW external validation

Run Condition A against the frozen source-derived CLDW validation layer. This is the historical-language transfer check and is directly comparable to the existing rules/spaCy/HF TOPONYM evaluation.

Do not run Condition B as though CLDW supplied a gold reference for every SH2026 spatial label; the existing CLDW source-derived validation layer was built from its place annotations and therefore supports the named-place comparison, not the entire expanded ontology.

## 5. Metrics

Primary TOPONYM metrics:

- exact-span precision, recall and F1;
- micro and macro aggregation.

Secondary boundary analysis:

- overlap-span precision, recall and F1.

LLM-specific audit measures:

- span-grounded / unsupported rate;
- evidence-grounded rate;
- contextual-inference rate;
- ambiguity rate;
- invalid-label rate;
- requires-review rate;
- latency;
- input/output tokens;
- estimated cost only when reconstructed from a dated, recorded price schedule.

For Condition B also report representational reach separately from within-label accuracy.

## 6. Anti-leakage and interpretation rules

- Do not alter `holdout_v1` after inspecting formal LLM errors.
- Do not tune the v1 prompt against formal holdout failures while continuing to call the same evaluation held out.
- Any revised prompt becomes a new explicitly versioned condition.
- Preserve raw structured responses, normalized grounded spans, prompt hash, source hash, benchmark hash, model/provider metadata and run manifest.
- A single generative run supports an observed-performance claim, not a stability claim.
- CLDW and synthetic results remain separately labelled.

## 7. Reproducible runner

The experiment runner is:

`python scripts/run_sh2026_llm_ner.py ...`

For the formal synthetic TOPONYM condition:

```bash
python benchmarks/build_holdout_v1.py
python scripts/run_sh2026_llm_ner.py benchmarks/holdout_v1.jsonl \
  --condition toponym \
  --provider openai \
  --model gpt-5.6-sol \
  --reasoning-effort none \
  --benchmark-mode \
  --frozen-at-commit <SH2026_BRANCH_COMMIT> \
  --expected-sha256 be9c526af68230f22cb92507af69d8aacea8cbb5bd7ad5dfcf3d7c16767fdb9b \
  --out-dir sh2026_outputs/llm_ner_toponym
```

`OPENAI_API_KEY` must be supplied through the environment. The runner intentionally does not accept API keys as command-line arguments.

After inference, `llm_ner_predictions.jsonl` can be re-scored with `--predictions` without another paid API call.

### Draft-PR execution control

GitHub only exposes `workflow_dispatch` after the workflow exists on the repository's default branch. While SH2026 remains on its draft feature branch, `.github/workflows/sh2026-llm-ner.yml` therefore also supports a deliberately narrow pull-request trigger: changing `config/llm_ner_scope` runs exactly the requested formal condition. Unrelated commits do not trigger paid inference.

The repository secret `OPENAI_API_KEY` is a hard precondition. If it is absent, the workflow stops before building datasets or making an API call. Secrets must never be committed, echoed into logs, or passed as command-line arguments.

## 8. Release criterion

The NER row is complete only after:

- constrained LLM TOPONYM predictions are frozen and scored on the synthetic holdout;
- the same TOPONYM condition is scored on the CLDW external-validation layer;
- the full-spatial LLM condition is frozen and scored on the synthetic holdout;
- all raw/normalized outputs and manifests are preserved;
- comparison figures are regenerated from tidy result files rather than hand-entered values.
